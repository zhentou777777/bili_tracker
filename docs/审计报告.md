## 二、P0 —— 阻断级问题

### P0-1 ★ 最高优先级：`AppCard(accent:)` 在高度无约束时抛断言 →「正在直播」卡片渲染即崩

**证据链**

1. 用户最近一次自检 `check_result.txt`（2026-10-02 15:57）里，`flutter test` 结果：

```
00:02 +41 -2: Some tests failed.
00:02 +41 -2: widget_test.dart: 共用组件 AppCard / SectionTitle / TagChip / EmptyState 可渲染 [E]
```

2. 报错原文直指部件与约束：

```
The offending constraints were:
  BoxConstraints(0.0<=w<=Infinity, h=Infinity)

The relevant error-causing widget was:
  Row Row:file:///.../lib/ui/widgets.dart:54:19
```

3. `lib/ui/widgets.dart:54` 正是 `AppCard` 的 accent 分支：

```dart
child: accent == null
    ? body
    : Row(
        crossAxisAlignment: CrossAxisAlignment.stretch,   // ← 第 54 行
        children: <Widget>[
          Container(width: 3.5, ...),                      // 左侧竖条
          Expanded(child: body),
        ],
      ),
```

**根因**：`CrossAxisAlignment.stretch` 要求交叉轴（此处是**高度**）**有界**，Row 才能把子项拉伸到父级高度。而 `AppCard` 被放进 `Column` / `ListView` 时，父级给的高度约束是 `0 <= h <= Infinity`（主轴无界）→ `stretch` 试图用 `height: Infinity` 布局子项 → `BoxConstraints` 归一化断言失败。

**影响面（真实且已上线）**：`lib/ui/today_page.dart:231` 的「正在直播」卡片正是在 `ListView`（`today_page.dart:170`）里用了 `accent: c.live`：

```dart
return AppCard(
  accent: c.live,            // ← 触发 bug
  ...
);
```

**即：只要有一个追更的 UP 主开播，「今日」页在渲染该卡片时就会抛异常（红屏 / 该卡不渲染）。** 因为「正在直播」区块只在有直播时才出现，平时看不到，所以很容易被漏测。测试恰好命中了它 —— **这个测试是对的，widget 是错的。**

**修复方案（二选一）**

- 最小改动：给 accent 分支的 Row 包一层 `IntrinsicHeight`，让它先量出有界高度：

```dart
: IntrinsicHeight(
    child: Row(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: <Widget>[
        Container(width: 3.5, decoration: ...),
        Expanded(child: body),
      ],
    ),
  ),
```

- 更推荐（彻底摆脱布局依赖，省掉一次 intrinsic 测量）：用**左边框**画竖条，去掉 Row：

```dart
: DecoratedBox(
    decoration: BoxDecoration(
      border: Border(left: BorderSide(color: accent!, width: 3.5)),
      borderRadius: const BorderRadius.horizontal(left: Radius.circular(18)),
    ),
    child: body,
  ),
```

（注意 `accent` 是 `Color?`，在 `accent != null` 分支里用 `accent!` 或先提升为局部变量。）

## 三、P1 —— 重要问题

### P1-1 `pubspec.yaml` 的 SDK 约束与项目实况严重不符

```yaml
environment:
  sdk: ">=3.0.0 <4.0.0"
  flutter: ">=3.10.0"
```

但项目自身文档明确要求 **Flutter ≥ 3.32**（`workmanager 0.9.0` 强制），Dart 实际是 **3.8.1**；且代码用了 `Color.withValues`（Flutter 3.27+）、`CardThemeData` / `DialogThemeData`（较新版本才有的类型）。后果：在 Flutter 3.10–3.31 上 `pub get` 会**通过版本检查**，然后在编译期报一堆看不懂的缺符号错误。

**建议**：

```yaml
environment:
  sdk: ">=3.8.0 <4.0.0"
  flutter: ">=3.32.0"
```

### P1-2 主题测试自身有 bug（必然失败，属测试缺陷）

`test/widget_test.dart:131-137`：

```dart
await tester.pumpWidget(probe(AppColors.light));
expect(seen.bg, AppColors.light.bg);     // 通过

await tester.pumpWidget(probe(AppColors.dark));
expect(seen.bg, AppColors.dark.bg);      // ← 第 136 行失败：拿到的是「浅色」
```

原因：`MaterialApp` 内部用 `AnimatedTheme` 做约 200ms 的主题插值。`pumpWidget` 换主题后**动画停在 t=0**，`Theme.of(context)` 仍返回旧（浅色）值，所以断言必然失败。

**修复**：断言前推进一帧动画：

```dart
await tester.pumpWidget(probe(AppColors.dark));
await tester.pump(const Duration(milliseconds: 250));   // 或 pumpAndSettle()
expect(seen.bg, AppColors.dark.bg);
expect(seen.isDark, isTrue);
```

### P1-3 开播轮询缺平台过滤（跨平台串台）

`lib/data/db.dart:474`：

```dart
Future<List<String>> upsWithLiveEnabled() async {
  ...
  where: 'push_live = 1',        // ← 没有 platform 过滤
}
```

`lib/service/sync_service.dart:442` 直接把这些 uid 丢给 **B 站专用**的 `fetchLiveStatus`。

目前「微博」是 `enabled: false`，所以没暴露；**一旦启用微博**，微博的 uid 会被当成 B 站 mid 发往 `api.live.bilibili.com`，产生脏请求。

**建议**：`upsWithLiveEnabled(platform)` 加平台参数，或 `checkLive()` 内按平台分组、只取 bilibili。

### P1-4 数据库无迁移路径

`lib/data/db.dart`：`_version = 1`，`_onUpgrade` 是**空实现**。将来加列/改表时，一旦忘了 bump version 或写迁移，老用户升级会崩或静默丢数据。

**建议**：把「改 schema = bump version + 在 `_onUpgrade` 按 oldVersion 分段写迁移」写进 README 与代码注释；哪怕现在只加一行 `throw StateError(...)` 提醒，也比留空安全。
