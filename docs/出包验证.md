# 出包之后，怎么确认包里真的是新代码

改完代码出了包，怎么知道 APK 里装的确实是新代码，而不是上一次的残留？

看文件修改时间是**不够**的。本项目真遇到过：Flutter 增量编译判定失误，只花 2.9 秒就打印
`√ Built ...app.apk`，但包里还是旧代码 —— 文件时间也是新的。反过来，时间新也只能证明文件被写过，
证明不了内容。

可靠的办法是**拆开 APK，在原生库里找你这次新加的那句话**。

---

## 方法

Flutter 的 Dart 代码在 release 包里被编译进 `lib/<架构>/libapp.so`，字符串常量以
**UTF-16LE** 存放（不是 UTF-8）。

所以：把 `libapp.so` 取出来，按 UTF-16LE 搜一句**这次新增的、独有的中文文案**。

同时要搜两个对照串，否则你不知道是「真的没有」还是「搜索方法本身失效了」：

- 一个**新旧都有**的串（例如界面标题）—— 它必须是 `True`，否则说明方法错了；
- 一个**只在旧版存在**的串 —— 它必须是 `False`。

---

## ⚠️ 一个必须知道的坑：字符串可能在奇数偏移上

这是 2026-10-02 实际踩到的：同一句文案，在 32 位包里搜得到，在 64 位包里搜不到。
一度被误判成「编译缓存陈旧」，白清了一次缓存。

**真正的原因在搜索方法本身。**

下面这种写法（很多教程都这么写）是**错的**：

```python
data = zipfile.ZipFile(apk).read('lib/arm64-v8a/libapp.so')
text = data.decode('utf-16-le')          # ← 从第 0 字节开始按 2 字节切
assert '新文案' in text
```

`decode('utf-16-le')` 从**第 0 字节**开始两两分组，因此**只能看见落在偶数偏移上的字符串**。
而不同 CPU 架构的常量池排布不同，同一个字符串在 arm64 里可能落在**奇数偏移**（实测在
`339445`，是奇数），在 armeabi-v7a 里却落在偶数偏移。于是同一份源码、同一次编译，
32 位包「搜得到」、64 位包「搜不到」—— 而代码其实**一直都在**。

**正确做法：按字节在任意偏移上扫描，不要先解码。**

### Python（推荐，跨平台）

```python
import zipfile, sys

def find_all(hay: bytes, needle: bytes):
    hits, start = [], 0
    while True:
        i = hay.find(needle, start)
        if i < 0:
            return hits
        hits.append(i)
        start = i + 1

def check(apk_path, arch, marks):
    data = zipfile.ZipFile(apk_path).read(f'lib/{arch}/libapp.so')
    print(f'--- {apk_path} [{arch}] {len(data)} 字节')
    for label, s, expect in marks:
        hits = find_all(data, s.encode('utf-16-le'))
        ok = (len(hits) > 0) == expect
        par = ','.join(str(h % 2) for h in hits[:3]) or '-'
        print(f'  {"OK " if ok else "!! "}{label:<16} 命中 {len(hits)} 次  '
              f'偏移 {hits[:3]}  奇偶 {par}  期望 {expect}')

# 三个都必须是 True；对照串自己按版本换
marks = [
    ('新增文案',   '弹幕姬里没有这个直播间',            True),
    ('新增文案2',  '进直播间，或看这个直播间的弹幕',      True),
    ('对照-新旧都有', '今日速览',                        True),
]
for arch, apk in [
    ('arm64-v8a',   'build/app/outputs/flutter-apk/app-arm64-v8a-release.apk'),
    ('armeabi-v7a', 'build/app/outputs/flutter-apk/app-armeabi-v7a-release.apk'),
    ('x86_64',      'build/app/outputs/flutter-apk/app-x86_64-release.apk'),
]:
    check(apk, arch, marks)
```

### PowerShell（本机是 Windows 时）

```powershell
function Find-AnyOffset([byte[]]$hay, [byte[]]$needle) {
  $n = $needle.Length; $last = $hay.Length - $n
  $hits = New-Object System.Collections.Generic.List[int]
  for ($i = 0; $i -le $last; $i++) {
    if ($hay[$i] -ne $needle[0]) { continue }
    $ok = $true
    for ($j = 1; $j -lt $n; $j++) { if ($hay[$i+$j] -ne $needle[$j]) { $ok = $false; break } }
    if ($ok) { $hits.Add($i) }
  }
  return ,$hits
}

$apk = 'build\app\outputs\flutter-apk\app-arm64-v8a-release.apk'
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z = [System.IO.Compression.ZipFile]::OpenRead((Resolve-Path $apk))
$e = $z.Entries | Where-Object { $_.FullName -like '*libapp.so' } | Select-Object -First 1
$ms = New-Object System.IO.MemoryStream; $s = $e.Open(); $s.CopyTo($ms); $s.Dispose()
[byte[]]$b = $ms.ToArray(); $ms.Dispose(); $z.Dispose()

$needle = [System.Text.Encoding]::Unicode.GetBytes('弹幕姬里没有这个直播间')
$hits = Find-AnyOffset $b $needle
"命中 $($hits.Count) 次，偏移 $($hits -join ', ')"
```

## 2026-10-02 的实际结果（供对照）

全量重编后，`v0.2.0+1` 的三个包：

| 架构 | `弹幕姬里没有这个直播间` | 命中偏移 | 奇偶 |
|---|---|---|---|
| arm64-v8a | 命中 1 次 | 339445 | **奇** ← 用旧方法会漏 |
| armeabi-v7a | 命中 1 次 | 1950604 | 偶 |
| x86_64 | 命中 1 次 | 339495 | **奇** ← 用旧方法会漏 |

如果当时用的是「先 decode 再 in」的写法，就会得出「64 位包里没有这句文案、32 位包里有」的
错误结论 —— 而真相只是偏移奇偶不同。

---

## 别把结论写过头

这套方法能证明的是：**这个字符串在这份 `libapp.so` 里存在**。

它**不能**证明：

- 这段代码在运行时真的会被执行到；
- 界面渲染正确；
- 功能符合预期。

所以它只是「防止发错包」的一道机械检查。真正的功能验证仍然要在真机上做。
