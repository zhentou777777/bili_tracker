## 一、问题根因（已定位，非跳转逻辑错误）

直播卡上有**两个**可点区域，且**没有任何视觉分隔**：

| 位置 | 当前行为 |
|---|---|
| 卡片主体（头像 / UP 名 / 标题那片） | 进直播间：`https://live.bilibili.com/{房间号}` → 深链 `bilibili://live/{房间号}` → 优先唤起 B 站 App，失败退回浏览器 |
| **右上角一个气泡图标**（`Icons.forum_outlined`，tooltip「打开弹幕姬」） | App 内 WebView 打开 `https://chat.vrp.moe/dashboard/{房间号}` |

全仓检索确认：**能到达 `chat.vrp.moe` 的入口只有这一个图标**（以及弹幕姬页右上角的「用浏览器打开」）。
卡片主体的深链转换（`bilibiliDeepLink`，`lib/platform/bilibili.dart`）已逐行核对，`live.bilibili.com/数字` → `bilibili://live/数字` 正确，**不会**指向 chat.vrp.moe。

→ **结论：不是跳转写错了，而是"一张卡两个落点、且图标看起来像卡片的一部分"。** 用户把图标当成卡片自身，点下去自然以为「点的是直播间」。

**附带疑点**：反馈中看到的是 `https://chat.vrp.moe/`（**根路径**，不是 `/dashboard/房间号`），怀疑 LAPLACE Chat 会把未配置的房间页重定向到首页 —— 待复测确认。

## 二、定稿需求

### R1 直播卡：改为「点一下 → 弹层选择」（方案 A）

- 点卡片**任意位置** → 弹出底部弹层。
- **卡片内不再保留任何图标按钮** —— 那个气泡图标就是误触源，删除。
- 弹层内容（自上而下）：
  1. **头部**：UP 头像 + UP 名 + 「直播中」标签 + 直播标题（过长截断）
  2. **主按钮：进入直播间** —— 主色 FilledButton，仍然是首选主行为
  3. **次按钮：打开弹幕姬** —— OutlinedButton，**必须带文字**，不能只有图标
  4. **取消**
- 语义：弹层是"选动作"，**不记忆、不设默认**，每次都要用户明确选一下（这正是"不误触"的代价，已确认接受）。
- 边界：**房间号为空时不弹层**，也不要崩。

### R2 弹幕姬：内嵌为主，异常自动转浏览器

- 默认仍在 App 内 WebView 打开 `https://chat.vrp.moe/dashboard/{房间号}`。
- 要求能识别**两类异常**并都给出路：
  1. **加载失败**（主文档 `onReceivedError`）—— 现状已有，保留；
  2. **被重定向到首页**（URL 离开 `/dashboard/...`、落到 `/` 或站点首页）—— **本次新增检测**，判定为"这个直播间在该站没有对应页面"。
- 异常时给出：明确文案（不是空白页）+ **重试** / **用浏览器打开** 两个出口 + 一次轻提示（不静默失败）。
- 异常时**不摘掉入口**（按确认：保留、提示、不自作主张删功能）。

### R4（后补）弹幕姬页要有「进入直播间」出口

弹幕姬页顶部（AppBar）加一个「进入直播间」按钮，走**同一套深链逻辑**
（`external_link.dart` 的 `openBilibiliContent`），不另写 `launchUrl`。

- 放 **AppBar** 而不是页面里：AppBar **在错误态也可见** —— 恰恰是「这个直播间在
  弹幕姬里没有页面」的时候，用户最需要这个出口。
- 房间号为空时该按钮不显示（与弹层里禁用「打开弹幕姬」的处理一致）。
- 两条路都失败时沿用既有兜底：复制链接 + 提示，绝不让点击「毫无反应」。

### R3 明确不动的部分（防回归）

- 深链转换与「优先唤起 B 站 App、失败退浏览器」策略**完全不变**（阶段 I 的成果，已实测 18/18）。
- 「进直播间」仍是**首选主行为**（在弹层里放主按钮）。
- 日历页 / 考古页 / 动态卡的点击行为不变。
