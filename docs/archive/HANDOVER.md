## 四、上手路径（按顺序做，别跳）

1. **装环境**：Flutter ≥ 3.10（必须，依赖 Dart 3）、JDK 17、Android SDK 34。
2. **补模板文件**：`flutter create --platforms=android .`
   这步不能省——`android/local.properties`（含 `flutter.sdk` 路径）由它生成，我手写的 `build.gradle` / `Manifest` / `styles.xml` 会被保留。
3. **拉依赖**：`flutter pub get`（13 个包的版本我都查过 pub.dev，不存在解析失败）。
4. **先跑探针**：`dart tools/probe.dart`，确认 23 项全绿。
5. **带 Cookie 再跑一次**：验证关注列表和动态解析。**有报错先看第七节的坑。**
6. **编译**：`flutter build apk --release`。
7. **真机验证闭环**：登录 → 今日页刷新 → 日历有数据 → 开播通知。

## 五、架构决策（为什么这么做，别误改）

| 决策 | 原因 |
|---|---|
| 不用 Drift，手写 SQL | Drift 依赖 `build_runner` 代码生成，沙箱跑不了。交付无法生成的半成品等于没交付 |
| 不用 `webview_flutter`，用 `flutter_inappwebview` | 官方 WebView **没有读取 Cookie 的 API**（只有 set/clear），而 SESSDATA 是 HttpOnly，JS 也读不到 |
| 自带 MD5，不引 `crypto` | 让 `tools/probe.dart` 零依赖可独立运行，核心算法能被真实验证 |
| Cookie 存 Keystore/Keychain，绝不上传 | 架构红线，服务端只收推送摘要且字段白名单过滤 |
| 开播检测走公开接口 | 实测无需 Cookie，App 被系统杀掉后服务端也能兜底 |
| 拉关注列表用 `insert ignore` + `update` 而非 `replace` | `replace` 会整体覆盖，把用户的分组、推送开关、上次同步时间全冲掉 |
| 请求带 `buvid3` 等设备指纹 | 只带 SESSDATA 必吃 `-352` 风控 |

## 七、已知的坑（踩过的和预判的）

- **风控 `-352` / HTTP `412`**：境外数据中心 IP 必然触发，真机移动网络正常。已做请求抖动 + 自动降速，遇到只能重新登录或降频。
- **动态 `card` 字段是 JSON 字符串**，且各 `type` 的有效字段位置不一致（专栏在根节点、视频在 `item` 下）。解析函数对每种 type 单独分支，取不到时降级为摘要，**不会因单条异常拖垮整页**——改这里要小心别破坏这个容错。
- **WorkManager 最小间隔 15 分钟**，且各厂商省电策略会跳过任务。开播提醒要可靠必须上服务端兜底。
- **`space/arc/search` 需要 WBI 签名**，且比其它接口更容易触发风控。我在同步流程里做了「投稿失败不阻断动态结果」的处理，不要改成直接向上抛。
- **WBI 密钥会变**（约一天一次），已做 6 小时缓存。若发现 `-403`，先怀疑密钥过期。
- **`android/` 目录是手写的**，与 `flutter create` 生成的模板可能有细微差异，跑不起来时优先对照官方模板排查。
