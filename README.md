# 追更台

关注的 UP 主一多，动态刷不过来，开播也总是错过。这个 App 把它们收到一个地方：今天谁更新了、谁正在播、哪天发了什么，翻一眼就看完。

安卓 App。用你自己的 B 站账号登录，数据只存在手机里。

## 下载安装

去 [Releases](https://github.com/zhentou777777/bili_tracker/releases/latest) 页面，按手机的 CPU 架构下对应的包：

| 下载这个 | 适合谁 | 大小 |
|---|---|---|
| **`app-arm64-v8a-release.apk`** | **不确定就下这个** —— 2017 年以后的手机基本都是它 | 19 MB |
| `app-armeabi-v7a-release.apk` | 2017 年前的老手机（32 位） | 17 MB |
| `app-x86_64-release.apk` | 模拟器，以及少数平板 | 20 MB |

要求 **Android 6.0 或更高**。

装的时候系统会提示「未知来源应用」，去设置里允许一下就好。

> 这个包用调试证书签名。**自己装着用没问题，但不能上架应用商店。**

## 它能做什么

**今日** —— 最近三天的动态，正在直播的排在最前面。
**日历** —— 按天翻，看哪天谁发了什么。
**UP 主** —— 关注列表，在这里勾选要追更的人。
**考古** —— 把已经抓下来的内容按关键词、UP 主、类型、时间搜出来。
**开播提醒** —— 本地通知，点一下直接跳进直播间。
**弹幕姬** —— 点直播卡，选「打开弹幕姬」，在 App 里看这个直播间的弹幕（用的是 [LAPLACE Chat](https://chat.vrp.moe)）。
**主题** —— 浅色、深色、跟随系统，设置里切。

点动态、直播、日历上的条目，都会**优先唤起 B 站 App**；唤起不了才退回浏览器。

## 第一次用

1. 打开 App，点「登录 B 站账号」
2. 屏幕上出现一个二维码，**用 B 站 App 扫它**。同一台手机也行 —— 会直接跳到 B 站 App 里让你确认
3. 登录完去「UP 主」页，把想追的勾上
4. 回「今日」页，右上角刷新

没装 B 站 App 也能用：登录页右上角有「网页登录」这个备用入口。

## 几件该知道的事

**只有安卓版。** iOS 没做，暂时也不打算做。

**开播提醒不是 100% 准时。** 安卓各家厂商的省电策略会拖延、甚至整轮跳过后台任务，晚几分钟是常事。

**请求太频繁会被 B 站风控。** 遇到 `-352` 或者验证码，重新登录一次，或者把抓取频率降下来。这是 B 站那边的限制，App 绕不过去。

**录播专区还没做。** 实测下来，没有不需要授权就能查任意主播直播回放的公开接口，所以这块先搁着。

**换手机或者重装 App，要重新登录。**

## 隐私

**没有服务端。** 所有请求都是 App 直接打到 B 站，中间不经过任何服务器。

登录凭证（Cookie）存在手机系统的安全存储里（Android Keystore），**不会上传，也没有任何地方能收到它**。

> 仓库里的 `server/` 是给以后做服务端推送准备的中继，**目前没有部署，App 也完全不依赖它**。

## 免责

这个工具用你自己的账号凭证访问 B 站接口，等同于你本人打开网页看自己关注的内容。使用即表示你了解并自行承担可能违反平台服务条款的风险。

## 自己编译

需要 Flutter 3.32+、JDK 17、Android SDK（NDK 27）。

```bash
flutter pub get
flutter build apk --release --split-per-abi
```

Windows 上可以直接双击 `REBUILD.bat`（它会清掉缓存做一次干净编译，避免增量编译的坑）。

开发文档在 [`docs/`](docs/)：架构、每个决定的理由、踩过的坑、出包后怎么验证。
